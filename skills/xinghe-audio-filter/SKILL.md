# 星禾音频筛选（xinghe-audio-filter）

## 这个 Skill 检查什么（一句话）

检查「星禾口语」的音频库清单，按「文件夹 / 格式 / 标签 / 关键词」四个维度筛选，并保证「有结果 / 无结果 / 清空恢复」三种状态都正确；此外额外检查清单的可访问性。

## 触发场景

- 用户说「筛选 / 查找 / 过滤」星禾口语里的音频或文件夹。
- 用户要按文件夹、文件格式、标签、标题关键词对素材列表做归类或查找。
- 需要验证筛选交互的三种状态（有结果、无结果、清空恢复）。
- 用户要求检查音频列表或筛选控件的可访问性。

## 操作步骤

1. **读取清单**：读取 `examples/audio-library.md`，拿到待筛选的音频库数据。每条素材至少包含字段：`标题`、`所属文件夹`、`格式`、`时长`、`标签`。
2. **解析筛选条件**：从用户输入里提取筛选维度，可选维度有四个——`文件夹`（按所属文件夹名）、`格式`（mp3 / m4a / wav / mp4 / mov）、`标签`（如「精听」「跟读」「听力」）、`关键词`（标题里包含的字符串）。
3. **执行筛选**：按条件逐条过滤清单，得到命中结果。
4. **处理三种状态**（必须都验证）：
   - **有结果**：命中若干条，逐条列出标题 + 文件夹 + 格式 + 时长。
   - **无结果**：条件过于苛刻导致命中 0 条时，明确返回「无匹配项」，并提示用户放宽条件（而不是静默返回空）。
   - **清空恢复**：清空所有筛选条件后，必须能回到全量清单，一条不少。
5. **写调用记录**：把本次调用的筛选条件、三种状态的结果、命中条数，追加到 `examples/filter-log.md`，作为调用证据。
6. **（可访问性加练）检查可访问性**：逐项核对以下三点，并给出「通过 / 不通过 + 改进建议」：
   - **文本标签**：每条素材是否有可被读屏器朗读的文本标签（标题、文件夹名清晰可见）。
   - **控件语义**：每个筛选维度是否有清晰的语义，用户能理解「按什么筛」。
   - **非颜色依赖**：任何状态（如选中、命中、无结果）是否只靠颜色传达信息，色盲/读屏用户能否同样理解。

## 约束

- 只做「筛选」，不做筛选之外的功能（不增删素材、不修改清单数据）。
- 筛选结果必须逐条可见、条数准确，不允许只回一句「已筛选」。
- 无结果时必须给出明确提示，不能假装有结果。
